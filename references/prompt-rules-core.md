## 一、画面通用准则（8 条，所有 Stage 适用，最高优先级）

跨场景、跨风格、跨品牌的「画面公理」。任何 Stage 0.5 / 1A / 1B / 2A / 2B 输出都必须通过；不达标必须重出。

### 合格底线（保画面不崩，5 条）

#### 准则 1：抽象语义符号化

抽象概念用 **1 个符号代表**，**禁止字面 N 个实例化**。

| 抽象语义类 | ❌ 字面 N 实例 | ✅ 1 个符号 |
| --- | --- | --- |
| 时间频率（周/月/年/天/N 次） | 7 张日历页、30 个签到格 | 1 个日历 / 1 张"7"字卡 / 1 个表盘 |
| 程度修饰（很多/超多/海量） | 30 个金币散落 | 1 个金币堆（"很多"用大小/光效表达） |
| 集合概念（团队/家人/伙伴们/一群） | 5 个人物 | 1 个代表 + 模糊轮廓背景 |
| 选择概念（多种选择/任你挑） | 5 个选项卡 | 1 个分叉路径 / 1 个三选一图标 |
| 持续概念（持续/不断/源源不断） | 30 个粒子 | 1 道流光 / 1 条无限符号 |

**Stage 0 表写法**：只列元素名（轻量对齐用），**不带数量前缀**（如"1 个 / 1 张"），**不带括号细节说明**。

**Stage 0.5 起强约束**：从画面元素组合表（5×9）开始，所有元素描述必须严守 **"1 个 X"格式**。

#### 准则 2：画面必须读得通

任意两个独立元素必须通过 **4 种方式之一**连接：

| 连接方式 | 描述 | 例 |
| --- | --- | --- |
| **物理连接** | 接触 / 重叠 / 包含 / 前后景 | 手碰礼盒、券压在礼盒上 |
| **视觉引导** | 动线 / 光线 / 箭头串联 | 礼盒射出光柱指向手机 |
| **重复呼应** | 颜色 / 形状 / 方向一致 | 5 个权益图标颜色统一、左右对称呼应 |
| **框架统一** | 共享背景 / 光源 / 地面 / 画框 | 人和咖啡都在咖啡店里、网格背景统一所有装饰 |

❌ 两个独立元素无连接、无引导、无呼应、无共享框架 → 画面被自动拆成两张图。

#### 准则 3：主体居中 + 留白集中 + 不被裁切

- 主体核心区落在画面 **中心 ±30% 范围**
- 主体外接框 ≥ 画面 **30%** 且 ≤ 画面 **70%**（防止主体撑破画面被边缘切掉）
- **主体必须完整呈现，不允许任何一边被画面边缘裁切**（无论是顶部 / 底部 / 左右 / 四角都不行；带阴影的物体连阴影也尽量在画面内）
- 留白要"集中"在一侧或一角，**禁止对角线两端有元素、中间空荡**

**Prompt 端硬禁词（写了 = 必然触发裁切）**：

| 禁词 | 为什么禁 | 替代写法 |
| --- | --- | --- |
| 极近裁切 / 特写裁切 / extreme close-up crop | 直接命令模型切主体 | "主体占画面 60%，居中，完整呈现" |
| 主体占画面 ≥70% / 主体撑满画面 / fills the canvas | 主体太大必出框 | "主体外接框约占画面 60%" |
| 屏幕占画面 80% / only the screen visible | 等价于"裁掉手机其他部分" | "手机完整呈现，屏幕区域是焦点" |
| 局部特写 / 半身裁切 / cropped half-body | 主动半切主体 | "中景，主体完整" |

**Prompt 端正向必写句**（每条 prompt 强烈建议附上）：

> "[主体名] 完整呈现不被画面边缘裁切，主体居中，四周留白均匀" / "[subject] fully visible, centered, with even margins on all sides"

#### 准则 4：主次权重 3 : 1.5 : 1

主体 : 副主体 : 装饰元素外接框 ≈ **3 : 1.5 : 1**

❌ 禁止 ≥ 2 个元素**完全平起平坐**，必须有清晰主次等差。

#### 准则 5：极简结构 + 主体内部纯净

UI 图标风格默认结构：「**1 主 + 0-1 副 + 0-1 嵌入式 icon + 3-4 同形装饰**」，**主体本身不能再嵌套立体副物**。

| 维度 | 硬约束 |
| --- | --- |
| **主体形容词前缀** | **禁用堆叠形容词**："装满 X 的 Y" / "塞满 X 的 Y" / "布满 X 的 Y" / "充满 X 的 Y" / "满载 X 的 Y" |
| **主体内部纯净** | 容器类（盒/箱/瓶）"打开"时只允许写"内部空，发光"或"放着 1 个 X"；禁止脑补 ≥2 件立体副物 |
| **主体表面规则** | **① 自动脑补禁止**：表面会被模型自动脑补图案的元素（日历/牌/票/屏幕/纸张），必须显式声明"表面无任何卡通图案 / 贴纸 / 插画 / 文字装饰"作反向闸<br>**② 显式 icon 允许**：可以显式声明 1 个抽象面性 icon 嵌入主体表面/角落 |
| **装饰元素数量** | 默认 **3-4 个同形小元素散落**；同一套方向只用 1 类装饰；5 套方向之间用不同装饰类型 |

**禁词清单**（写了 = 违反准则 5，必须重写）：装满 X 的 Y / 塞满 X 的 Y / 布满 X 的 Y / 充满 X 的 Y / 多类装饰堆叠 / 立体台历样式 / 卡通可爱图案 / 表面有花纹 / 内部塞着金币和小礼物 / 装满金色光芒。

> **嵌入式 icon ≠ 表面装饰图案**：1 个显式声明的抽象面性 icon 属于受控的"语义补充层"，与禁词清单不冲突。

### 美感增强（让画面更和谐，3 条）

#### 准则 6：动势同向

多装饰元素必须满足以下 3 种动势之一：**向中心收敛** / **从中心扩散** / **跟随主体动势**。

❌ 禁止"四面八方乱飞"。

#### 准则 7：透视方向统一

画面所有元素必须遵循同一个镜头视角：正面 / 俯视 X° / 仰视 X° / 侧 X°。**5 套方向之间至少覆盖 3 种不同视角**。

❌ 禁止部分正面 + 部分侧面混搭。

#### 准则 8：色彩主色相数 ≤ 5

整张画面色相数 ≤ 5（含背景），推荐：**1-2 个主色 + 1 个撞色点缀 + 1-2 个中性/金属色**。**5 套方向之间至少 3 种不同主色调**。

## 二、嵌入式抽象面性 icon（独立画面层）

### 定义

**嵌入式 icon** = 显式声明的、抽象的、面性几何/拟物图标，嵌入主体表面或角落或屏幕内部。第三层语义补充。

### Icon 在 3 类字面词中的角色

| 字面词类型 | icon 角色 | 示例 |
| --- | --- | --- |
| **完全具象**（解锁/抽奖/签到/邀请） | 可选——作情绪/补充语义点缀 | "抽奖"画面用闪电 icon 强化"惊艳"情绪 |
| **半具象**（拼团/免费/学习） | 必配——承接相对抽象那个汉字的语义 | "拼团"用群组 icon 承接"拼"的抽象集合语义 |
| **完全抽象**（分享/关注/订阅/收藏/点赞） | **必配且核心**——承接字面词核心语义本身 | "分享"由分享箭头 icon 承担"分享"语义 |

> 完全抽象词的 icon 必须来自公共面性 icon 库（详见 `element-library.md`）。**绝不允许业务定制造词**。

### 形态硬约束

| 维度 | ✅ 合法 | ❌ 非法 |
| --- | --- | --- |
| **图形** | 单一形态几何/拟物面性 icon | 带文字数字的徽章 / 带复杂插图的贴纸 |
| **填充** | 纯色填充（可带微立体厚度） | 多色复杂渐变 / 超薄描边 |
| **数量** | 每套方向**最多 1 个 icon** | ≥2 个 icon 会和主体抢戏 |
| **大小** | icon 外接框 ≤ 主体 **30%** | 占比 > 30% 会变成副主体 |
| **业务绑定** | 完全通用，不绑业务 | 业务定制 icon（品牌 logo / 文字 tag） |

### 嵌入位置（B1 / B2 / B4，3 种合法位）

**核心原则**：icon 必须和主体**强联系**——贴在主体表面、嵌在主体的数字界面里、压在主体角落。**不允许浮空、不允许飘在远处**。

| 位 | 写法 | 适用主体 |
| --- | --- | --- |
| **B1 表面贴** | icon 直接贴在主体的侧面 / 表面（与表面共平面或微凸起） | 立体容器（礼盒/宝箱/信封）、立体物（书本/钱包/购物袋）、屏幕背面 |
| **B2 屏幕显示** | icon 出现在数字界面内部（手机/iPad/UI 卡片屏幕里） | **只能配合数字界面主体**，不能用在礼盒/宝箱等非屏幕主体 |
| **B4 角落徽章** | icon 贴在主体的某一角（咬合在主体轮廓边） | 所有有清晰角的主体；**不适用**圆形主体 |

❌ 已废弃位置：**B3 上方浮起**（与主体语义脱钩）/ **B5 撑破缝隙旁**（画面已经够乱）。

## 三、9 个合法组合矩阵（5 种关系 × 3 种 icon 位）

5 套方向**必须**从下面 9 个组合里挑（5 套至少覆盖 3 种不同 A 关系）。**禁止**自由组合。

| 组合编号 | A 关系 + B icon 位 | 抽象骨架 | 通用 A 候选 | 通用 B 候选 | 通用 icon 候选 |
| --- | --- | --- | --- | --- | --- |
| **C1** | A1 容器 + B1 表面 | A 装 B，A 表面贴 icon | 礼盒 / 宝箱 / 购物袋 / 钱包 / 信封 | 1 张卡 / 1 本书 / 1 件商品 / 1 张钞票 | 分享箭头 / 心形 / 对勾 / 加号 |
| **C2** | A1 容器 + B2 屏内 | 数字界面 A 里装 B，屏幕里有 icon | 3D 手机 / iPad / UI 卡片 / 电视屏 | 1 张券 / 1 个商品 / 1 段视频缩略 / 1 个头像 | 分享箭头 / 铃铛 / 心形 / 播放三角 |
| **C3** | A2 出入 + B1 表面 | B 从 A 里撑破/飞出，B 表面贴 icon | 手机壳子 / 宝箱 / 信封 / 抽屉 | 礼盒 / 文档 / 立体字 / 单张卡 | 闪电 / 火焰 / 加号 / 对勾 |
| **C4** | A3 动作 + B1 表面 | A（手/角色）传递 B，B 表面贴 icon | 双手 / 一只手 / IP 角色 | 礼盒 / 课本 / 红包 / 邀请函 | 分享箭头 / 心形 / 对勾 / 加号 |
| **C5** | A3 动作 + B4 角落 | A（手/角色）传递 B，B 角落贴 icon | 双手 / 一只手 / IP 角色 | 礼盒 / 卡片 / 邀请函 / 文档 | 心形 / 闪电 / 加号 / 对勾 |
| **C6** | A4 承载 + B1 表面 | A 立在 B（底座）上，A 表面贴 icon | 礼盒 / 奖杯 / 书本 / 单张卡 | 日历 / 台阶 / 底座 / 平台 | 闪电 / 心形 / 对勾 / 上箭头 |
| **C7** | A4 承载 + B4 角落 | A 立在 B（底座）上，A 角落贴 icon | 奖杯 / 礼盒 / 书本 / 头像 | 台阶 / 底座 / 平台 / 颁奖台 | 五角星 / 心形 / 对勾 / 火焰 |
| **C8** | A5 重叠 + B1 表面 | A（大）和 B（小）轮廓 20-40% 重叠，A 表面贴 icon | 礼盒 / 购物袋 / 文档 / 卡片 | 日历 / 价签 / 标签 / 小卡 | 分享箭头 / 闪电 / 心形 / 对勾 |
| **C9** | A5 重叠 + B4 角落 | A 和 B 轮廓重叠，A 未被覆盖的角贴 icon | 礼盒 / 文档 / 卡片 / 书本 | 日历 / 标签 / 价签 / 小卡 | 心形 / 闪电 / 对勾 / 加号 |

### 选组合编号的快速判定

| 想表达的画面动作 | 选 |
| --- | --- |
| 礼盒里装着小物 | C1（A1+B1） |
| 手机屏幕里有商品/券 | C2（A1+B2） |
| 物件破壁/飞出 | C3（A2+B1） |
| 手/角色递东西，icon 在主表面 | C4（A3+B1） |
| 手/角色递东西，icon 在主角落 | C5（A3+B4） |
| 物件立在底座上，icon 在主表面 | C6（A4+B1） |
| 奖杯立颁奖台，icon 在主角落 | C7（A4+B4） |
| 礼盒压日历（上下重叠），icon 在主表面 | C8（A5+B1） |
| 卡片叠价签（左右重叠），icon 在主角落 | C9（A5+B4） |

### 5 套方向选组合的硬约束

- 5 套方向必须**至少覆盖 3 种不同 A 关系**（如 A1+A3+A5）
- **同一组合编号最多用 2 套**（避免 5 套都是 C1）
- **每套方向只用 1 种组合编号**，不允许混搭

### 禁用关系（写了 = 直接判失败）

| 禁用关系 | 禁用理由 |
| --- | --- |
| ~~共存关系~~（A 立于 B 旁/前/后） | 粘合度太弱，必然退化为拼贴 |
| ~~环绕/包围关系~~（多个 B 围着 A 成弧） | 与准则 1「1 个 X」冲突 |
| ~~串联/介质关系~~（A 和 B 通过 C 串起来） | 介质 C 容易抢主体戏 |
| ~~单纯穿插/穿透关系~~ | 仅限"长条物穿薄片"；"撑破"归到 A2 出入 |
| ~~拼贴关系~~ | 主副无可命名的自然关系 |

## 四、副主体语义关系类型（A1-A5）

| # | 关系类型 | 写法范式 | 通用示例 | 关键约束 |
| --- | --- | --- | --- | --- |
| **A1** | **容器关系** | A **里装着** B | 礼盒装日历 / 信封装贺卡 / 手机屏装一张券 | A 必须是立体容器或数字界面，不能是平面薄片 |
| **A2** | **出入关系** | B **从** A **里飞出/弹出/撑破** | 礼盒撑破手机屏冲出 / 数字 7 从宝箱弹出 | 重点是**运动状态**；剧烈程度：弹出 < 喷出 < 撑破 |
| **A3** | **动作关系** | A **对** B **做动作**（捧/递/抓/抱） | 双手捧礼盒 / IP 角色抱奖牌 / 一只手送红包 | A 必须是拟人主体（手 / IP 角色 / 卡通人） |
| **A4** | **承载/骑乘关系** | A **坐/站/骑在** B **上** | 礼盒站在日历上 / 奖杯立在台阶上 | B 表面必须能承重；**A 是被托的主**，**B 是底座（副）** |
| **A5** | **重叠/局部覆盖关系** | A 与 B **轮廓 20-40% 像素重叠**（含上下/左右结构） | 礼盒压日历右下角 / 购物袋叠在价签上 | **必须主大副小 ≈ 2:1**（参考准则 4） |

### A2「出入」vs 单纯「穿插」边界

| 维度 | A2 出入 | 单纯穿插（禁用） |
| --- | --- | --- |
| 重点 | **运动状态**（动势主导） | **静态截面**（凝固主导） |
| 典型 | "礼盒从手机里飞出"（B 正在离开 A） | "丝带卡在日历孔里"（B 同时位于 A 内外两侧） |
| UI 场景 | 高频使用 | 几乎用不到 |

### A 撑破 B 的合理性条件（任一满足）

| 条件 | 通过例 | 不通过例 |
| --- | --- | --- |
| ① B 是边界/容器，A 应该被 B 容纳但超出能力 | 礼盒撑破手机屏（屏装不下礼盒） | 铅笔穿礼盒（礼盒不该装铅笔） |
| ② A 从 B 内部生成/弹出，B 是 A 的"母体" | 课时券撑破通知卡边框 | 数字 7 穿日历页（数字本就该印在日历上） |
| ③ A 和 B 在叙事里有"包含→突破"的因果链 | 奖品撑破礼盒盖（礼物太多） | 羽毛笔穿过课时券 |

## 五、Stage 0 前置：关键词预处理（agent 自主完成）

文案里的字面词常有冗余/同义。**进入 Stage 0 前 agent 必须自主合并/去重**：

| 情况 | 处理 | 例 |
| --- | --- | --- |
| 修饰词 + 被修饰词 | 合并到具体载体词 | "主题内容" → 「内容」<br>"超值好礼" → 「好礼」 |
| 近义词 / 同义词同文案出现 | 合并为最具象的那个 | "课程 + 知识 + 学习" → 「内容」<br>"奖品 + 礼物 + 福利" → 「好礼」 |
| 通用动作词被其他词涵盖 | 省略独立行 | "分享领好礼"→"领"被"分享+好礼"自然涵盖 |
| 价格修饰 + 福利动作 | 各自保留为副元素候选 | "免费学" → "免费"和"学"都作副元素候选 |
| 双义同体 | 不在预处理处理，走「字面词 → 具象映射拆解」 | "拼团" = 拼+团 → 半具象 |

**合并产出**：
- 真正进入 Stage 0 表的字面词控制在 **3-5 个**
- **合并理由必须在 Stage 0 表上方用 1 句话说明**（例：「已合并'主题→内容'：主题为修饰词，作内容卡封面标题自然带过」）

## 六、Stage 0 中阶：字面词 → 具象映射拆解（找 L2 之前的强制热身）

### 核心心法：第一眼识别测试

看到一个具象物，**第一眼脑里冒出的词必须就是字面词本身**，禁止任何近义词跳跃。

| 通过例 | 跳层例（禁止） |
| --- | --- |
| 拼图块 → 第一眼"拼图"→ "拼" ✓ | 剪开的派 → 第一眼"派/切派"（不是"分享"，跳了"切给别人吃"一层）❌ |
| 邀请函 → 第一眼"邀请" ✓ | 钢笔尖 → 第一眼"笔"（不是"签到"，跳了"签字→签到"一层）❌ |
| 钥匙+锁 → 第一眼"开锁/解锁" ✓ | 图钉 → 第一眼"钉子"（不是"签到"，跳了"打卡→签到"一层）❌ |

### 字面词 3 类分类（单题判定）

**判定问题**：能否找到 1 个具象实物，看到它的人**第一眼就脱口而出字面词本身**？

| 答案 | 类型 | 典型例 |
| --- | --- | --- |
| ✅ 整体即可秒懂 | **完全具象** | 解锁（钥匙+锁）/ 抽奖（转盘）/ 签到（签到本+笔）/ 邀请（邀请函）/ 闯关（关卡门）/ 夺宝（宝箱）/ 礼盒 / 奖品 / 课本 |
| ⚠️ 整体不行，但拆字后每个汉字都能找到秒懂实物 | **半具象** | 拼团（拼=拼图 ✓ + 团=团体 ✓）/ 免费（免=撕标签 ✓ + 费=钞票 ✓）/ 学习（学=书 ✓ + 习=重复练习 ✓） |
| ❌ 整体不行，拆字后每个汉字也找不到秒懂实物 | **完全抽象** | 分享 / 关注 / 订阅 / 收藏 / 点赞 / 喜欢 / 推荐 / 连接 |

### L2 处理路径

| 类型 | L2 路径 | icon 角色 |
| --- | --- | --- |
| **完全具象** | 直接找 5 个 1:1 秒懂实物 | 可选 |
| **半具象** | 从拆字后两个汉字的实物池**混合凑 5 个** | **必配**——承接相对抽象那个汉字的语义 |
| **完全抽象** | L2 抓"动作的对象/载体"作主副主体的具象支撑 | **必配且核心**——承接字面词核心语义，必须来自公共面性 icon 库 |

| 维度 | 找什么 | 「拼团」例 | 「解锁」例 |
| --- | --- | --- | --- |

### 通道 A：联想合理性自检

## 十一、主次三层结构

| 平铺 / 平整 / lying flat | 静态没张力 | 微弯飘动 / 边缘上卷 / 错落叠放 |
| 正立 / 正面朝前 / facing forward | 视角呆板 | 3/4 视角倾斜 / 微仰 / 微俯 |
| 居中对齐 / 规整排列 / aligned | 元素无交互 | 高低错落 / 喷射放射 / 螺旋分布 |
| 静态摆放 / 静止 / static | 无运动暗示 | 凝固瞬间 / 刚刚发生 / 半空中 |

**纸质物（券/卡/红包/票）特别约束**：禁止"平铺/对齐"，必须用以下任一方式让它生动 —— 边缘卷起、微微倾斜、半空飘浮、错落叠放、风中翻转、被气流吹动。

## 十三、Stage 2A：构图变体表

用户从 Stage 1 的 5 张里选 1 个方向后，Codex 推理段 对该方向出 5 行构图变体表。

### 核心心法（v7.2 新增，最关键）

**Stage 1 选的是"元素"（主体+副体+icon+装饰），Stage 2 是用这些元素重新跑构图发散**。
保持元素绑定不变（如「手机+券+¥」），但在 9 组合矩阵（C1-C9）里换不同 A 关系来重排骨架，
而不是固守 Stage 1 选中的那个 C 编号、只变视角和姿态——后者会让 5 张变体本质同构、看着像 5 张近似图。

### 硬约束（与 Stage 1 对齐）

| # | 约束 | 说明 |
| --- | --- | --- |
| 🚪 1 | **5 套变体必须覆盖 ≥3 种不同 C 组合编号** | 与 Stage 1「5 套至少覆盖 3 种 A 关系」逻辑对齐；同一 C 编号最多用 2 套 |
| 🚪 2 | **元素绑定不变** | Stage 1 选定的「主体+副体+icon+装饰」元素列表 5 套都要包含（角色可换：A↔B 互换、副元素降为装饰也行，但元素本体必须在场） |
| 🚪 3 | **至少 1 维"动感/姿态" + 1 维"C 编号"** | 5 套之间在动感维度和 C 编号维度上都必须有可见差异 |

### 推荐 4 维（差异维度由 Codex 推理段 选，必含 C 编号 + 动感）

| 主体类型 | 推荐 4 维（**C 编号** + **动感维度** 加粗） |
| --- | --- |
| 人物主体 | **C 编号（C4/C5 为主）** / 表情 / **姿势/动作瞬间** / 服装 |
| 物品主体（立体物：礼盒/容器/3D 道具） | **C 编号（C1-C9 任选）** / 视角 / **主体动感瞬间** / 镜头距离 |
| 纸质主体（券/卡/红包/票） | **C 编号（C1/C2/C8/C9 为主）** / 视角 / **卷边/飘动状态** / 元素叠放层次 |
| 场景主体 | **C 编号（C4/C6/C7 为主）** / 构图重心 / 时间氛围 / **焦点元素运动** |

> 「C 编号」这一维度的取值范围是 **C1-C9**，不是「同一 C 编号下变视角」。如果不变 C 编号、只在视角/姿态上换花样，5 张变体会本质同构，违反 Stage 2 的存在意义。

### 输出表模板

```markdown
| 变体 | C 编号（A 关系） | 维度 B（动感） | 维度 C | 维度 D |
| --- | --- | --- | --- | --- |
| 2K：【变体名】 | C2（A1+B2 容器） | … | … | … |
| 2L：… | C3（A2+B1 出入） | … | | |
| 2M：… | C4（A3+B1 动作） | … | | |
| 2N：… | C6（A4+B1 承载） | … | | |
| 2O：… | C8（A5+B1 重叠） | … | | |
```

Codex 推理段 应在表格上方明确列出 4 个维度名称及理由（1-2 句）。

### 自检失败处理

- 5 套变体里 C 编号种类 < 3 → agent 内部强制重出 Stage 2A 表，不打扰用户
- 同 C 编号用 ≥3 套 → 同上重出
- 元素绑定丢失（5 套里有 1 套缺了 Stage 1 选定的元素）→ 同上重出

## 十四、有参考图时的硬约束

### 通用原则：参考图只取风格，组合编号自由发散

参考图的视觉信息分两层使用：
- **风格层**（配色 / 质感 / 光影 / 笔触 / 氛围 / 立体感程度）：喂给生图模型自动对齐，**不写进 Prompt 文字**
- **内容层**（参考图里出现的具体主体 / 副元素）：**5 套方向中最多 1 套**可以贴近参考图主体形态；其余 4 套不主动避开，但要遵守"5 套至少覆盖 3 种 A 关系"

**核心防御目标**：防"5 套方向被参考图带着走、集体落到同一个组合编号"，不是"禁止参考图里出现的物体"。

### 用户授权例外（解锁额外参考层）

默认严格版本。用户明确说出以下表述时按对应规则放宽：

| 用户表述 | 解锁层级 | 放宽行为 |
| --- | --- | --- |
| "参考这张图的风格"（默认/未说） | 仅风格层 | 现有规则不变 |
| "参考构图布局" / "按这个排布" / "用这种主副关系" | + 结构层 | 5 套方向都用相同组合编号；不再要求覆盖 3 种 A 关系 |
| "复用这个 X" / "这个礼盒/角色我要保留" | + 局部内容层 | 指定元素可复用。**复用对象是 IP 角色时必须切到 `prompt-rules-ip.md`** |
| "按这张图改改细节" / "微调" / "我就要这种" | 全层解锁 | 5 套方向尽量贴近参考图 |

## 十五、换参考图必要确认（逐字使用，不允许改写）

当用户提供了与上一轮不同的参考图，**必须先问用户**：

> 检测到新参考图与上一轮提示词的颜色方向不一致。请确认：
> 1. 颜色跟新参考图走（删掉提示词里的颜色词，颜色完全由新参考图决定）？
> 2. 还是保留原来的颜色方向（在 Prompt 里补回颜色描述词，以文字颜色覆盖参考图颜色）？

- 用户选「跟新参考图走」：删除所有颜色和质感描述词，Prompt 只保留主体 + 构图描述
- 用户选「保留原颜色」：在 Prompt 中显式补充颜色描述词，并告知用户此时文字颜色权重高于参考图

## 十六、给 Codex 推理段 的 Prompt 要求

- 主体突出，装饰简洁，适合用户给定的使用场景
- 默认是一个主体组合，不要生成复杂多主体场景
- 中文 Prompt 和 English Prompt 都要可直接喂给生图模型
- 只写元素、构图和配色，不要过度解释表达逻辑，不要列风险点
- 如果没有参考图，先给 3 个可选风格方向让用户选；用户说"直接默认"时用干净柔和的轻量 UI 插画风
- **Stage 1B 写 Prompt 时必须按 `composition-templates.md` 的 C1-C9 fill-in-blank 模板填空**，不允许自由发挥
- **Prompt 里绝对不允许写风格、质感、配色、光影等视觉描述词**（如"果冻质感""奶油白""渐变""3D 立体感"），除非用户明确授权
- Prompt 只描述主体、副元素、构图关系和元素之间的空间关系
- **Prompt 开头必须写明**：「只参考参考图的风格、配色、质感、线条和氛围，不借用参考图的主体、内容、构图和具体元素。」
