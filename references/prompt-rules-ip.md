# IP 双参考图模式（仅 IP 复用时读）

> **核心原则**：确认“风格图”和“IP 图”两个参考角色。同一张图允许同时承担两种角色，并按顺序重复传入；有两张图时按用户指定分工，不自行猜测或颠倒。
> **迁移说明**：本文件中的旧效果比例来自历史运行记录，不是当前 Codex 内置 `image_gen` 的实测结论。原版关于同图传入 0% 的禁止依据不再采用；当前效果须实际生成后查看。

## 触发条件（任一）

- 用户说"用图里的 IP" / "保留这个角色" / "这个 IP 我要复用" / "做品牌 IP 相关图"
- **Agent 在 Stage -1A 视觉清点参考图时识别出明显的 IP 形象**（带特定配饰的拟人角色 / 品牌吉祥物 / 卡通主体等，**不论场景类型**）
- Agent 在 Stage 0 检测到 IP 角色被锁定为固定主主体

> **触发判定红线**：触发与否取决于「参考图里有没有 IP 形象」+「用户是否明确说复用」，**不取决于"是缺省图/弹窗/引导页"等场景类型**。场景类型只决定视觉群组上限，不决定是否走 IP 模式。
> 即使是缺省图，如果参考图里没有 IP 形象、用户也没说要复用，就走非 IP 模式；
> 即使是普通运营图，如果参考图里含 IP、或用户说要复用，就必须走 IP 模式。

## 触发后 agent 必做动作

### 步骤 1：确认两个参考角色（不能跳过）

```
① 参考图 1 = 风格图（作色调/质感/底色/氛围参考）
② 参考图 2 = IP 图（锁定用户指定的角色）

同图可兼任两者，调用时重复传入同一绝对路径。
有双图时遵从用户说的哪个做风格、哪个做角色；已明确的分配直接沿用并回读。
角色仍不明确时才询问，不能因为同图兼任而强制补第二张不同的图。
```

### 步骤 2：告知历史效果与当前验证边界（避免预期错配）

以下数字仅来自旧运行记录。向用户说明这是历史经验，Codex 内置 `image_gen` 尚无本任务实测比例，不能承诺同样效果。

```
IP 双图模式（真双图 + 裸固定句式）实测能让 IP 主体识别度达到 70-80%
（黑白条纹/兔耳/面具脸等主特征还原）。

次要装饰（齿轮腰带 / 特定颜色配件）约 20-30% 概率丢失，
可在第二轮加 must-preserve hint 补救。

如果你需要严格 1:1 还原原 IP，建议走 PS 抠图后贴回的方案，
或者再给我 4-6 张同一 IP 不同动作角度的图。
```

### 步骤 3：用户确认 → 走双图流程

| 用户选择 | 处理 |
| --- | --- |
| 继续走双图 + 裸固定句式 | 进入步骤 4 |
| 要 PS 抠贴 | skill 不再生 IP，只生"无 IP 的场景图"，留 IP 位置给用户后期合成 |
| 能给多张 IP 图 | 收齐后传给模型（按当前 Codex 内置 `image_gen` 参考输入能力处理，见 codex-imagegen.md；不沿用旧接口的数量上限承诺） |

## 步骤 4：双图分图自检（写 prompt 前）

| 检查项 | 通过标准 | 不通过怎么办 |
| --- | --- | --- |
| 风格和 IP 两个角色已明确吗 | ✅ 用户分配明确，或同图兼任两者并重复传入 | 只追问未明确的角色 |
| 图 2 中的目标 IP 能确认吗 | ✅ 已实际查看并确认用户指定角色；不要求必须是干净单图 | 目标角色无法辨认时询问用户 |
| 图 1 是用户想要的整体风格吗 | ✅（不限于纯空背景，可含 IP 场景图） | OK |

**第 4 步没过禁止进入步骤 5**。

## 步骤 5：默认裸固定句式（首选）

### 强制开头句式（中文）

> IP 形象贴近参考图 2，参考参考图 1 的风格、配色、质感、线条和氛围，其余元素按描述重新生成。[IP 动作]；[副元素]；[1 个面性 X icon 位置]；[N 个 X 散落 + 动势]；[透视]；IP 和[副主体]表面无任何卡通图案/贴纸/插画/文字装饰，仅允许 1 个面性 X icon。

### 强制开头句式（English）

> IP design closely matches reference image 2, only reference style, color, texture, lines and atmosphere from reference image 1, all other elements regenerated per description. [IP action]; [secondary element]; [1 filled X icon position]; [N X scattered + motion]; [perspective]; IP and [secondary] surfaces have no cartoon patterns / stickers / illustrations / text decorations, only 1 filled X icon allowed.

**历史实测（非当前 Codex 内置 `image_gen` 结论）**：纯固定句式 + 真双图曾记录 IP 主体识别度 70-80%。**先跑这一版，看用户是否满意**。

### 模板示例（合规版）

```
IP 形象贴近参考图 2，参考参考图 1 的风格、配色、质感、线条和氛围，其余元素按描述重新生成。
单手举起 1 个拔出的电源插头到头顶上方，仰头端详的凝固瞬间，线缆风中翻转下垂，插头微微抖动；
1 个面性 × 关闭 icon 贴在插头表面正中；4 颗小三角粒子散落，跟随主体手势向上扩散；正面微仰 10°；
IP 和插头表面无任何卡通图案/贴纸/插画/文字装饰，仅允许 1 个面性 × icon。
```

### 反例（禁止写法）

```
❌ 1 个戴围巾的毛茸茸小娃娃 IP 角色（IP 形象贴近参考图），单手举起拔出的电源插头……
   ↑ 同时写"戴围巾/毛茸茸"和"贴近参考图"，模型会按文字描述重画
   ↑ 没区分参考图 1 / 参考图 2，无法绑定双图

❌ IP 角色 + 风格贴近参考图（单图）……
   ↑ 未明确风格 / IP 两个参考角色；同一原图可兼任两者，但需明确角色并重复传入
```

## 步骤 6：仅在用户反馈"某细节没对"时才加 must-preserve hint（补救）

> 这一步**不要主动用**——只在步骤 5 跑完后，用户反馈"齿轮腰带没了"/"颜色不对"等具体细节时才上。

### 写 must-preserve hint 之前必做（视觉验证）

1. **Read 参考图 2** —— 看清 IP 实际长什么样
2. **逐项验证用户/自己想 hint 的特征** —— "围巾"在图 2 里吗？"齿轮腰带"在图 2 里吗？
3. **如果用户说"保留 X"但 X 不在图 2 里** —— 立刻反问"参考图 2 里我没看到 X，你是想让我加上 X 还是想保留 [图 2 里实际有的 Y]？"
4. **禁止凭文字记忆 / 上一轮的图 / 自己的视觉幻觉写 hint**

### must-preserve hint 写法 5 条硬约束

| # | 约束 | 示例 |
| --- | --- | --- |
| 1 | 必要特征数量 **≤ 3** | 超过 3 个会让模型混淆 |
| 2 | 特征**名词性 / 名词短语，不带形容词** | ✅"齿轮腰带" / "兔耳"；❌"可爱的小齿轮腰带" |
| 3 | **不写颜色 / 质感 / 比例** | 这些从参考图 2 自动取 |
| 4 | **不写整体形象词** | ❌"黑白条纹熊猫造型"、"圆头小角色" |
| 5 | 必要特征必须是参考图 2 实际有的视觉元素 | 写 hint 前必须 Read 一次参考图 2 逐项验证 |

### must-preserve hint 反例

```
❌ 凭幻觉写不存在的特征：
   IP 形象贴近参考图 2（必须保留参考图 2 中 IP 戴的围巾）……
   ↑ 但参考图 2 实际没有围巾

❌ 整体形象描述：
   IP 形象贴近参考图 2（必须保留小毛茸茸娃娃的可爱围巾、圆头形象、紫色调）
   ↑ "小毛茸茸娃娃"是整体形象描述
   ↑ "可爱"是形容词
   ↑ "紫色调"是颜色（违反约束 3）

❌ 数量超标 / 普通特征：
   IP 形象贴近参考图 2（必须保留 1 条围巾、1 个帽子、1 个面具脸、1 双脚、1 双手）
   ↑ 特征数量 > 3
   ↑ "1 双脚 / 1 双手"是普通生物特征不是 IP 标识

✅ 视觉验证后的合法写法：
   IP 形象贴近参考图 2（必须保留参考图 2 中 IP 的齿轮腰带和兔耳），…
   ↑ 2 个特征，都是名词，且参考图 2 实际有的标志性元素
```

## 历史已知缺陷（旧双参考流程，未经 Codex 内置 `image_gen` 复测）

- **风格图 vs IP 图打架** —— 单 IP 图为主时圆形背景退化，含场景圆底为主时 IP 细节丢失。本质是模型在两张图之间做平衡，无法两全
- **IP 主体仍是 image2 偏好的 3D 立体** —— 即使 IP 图本身是 3D，模型也会按自己习惯重画
- **细节丢失率约 20-30%** —— 一些次要装饰（齿轮腰带、特定颜色配件）需要 hint 强化才能保留

## 必须明确两个参考角色（允许同图兼任并重复传入）

| 参考图 | 用途 | 缺失后果 |
| --- | --- | --- |
| **参考图 1：风格图** | 取色调 / 质感 / 线条 / 氛围 / 底色 / 整体调性 | 风格不稳，5 套各异 |
| **参考图 2：IP 角色图** | 提升 5 套图之间的 IP 一致性 | 5 套 IP 像 5 个不同角色 |
| 参考图 3+：IP 多角度图（可选，建议） | 让模型理解"必要特征" | 细节特征被简化 |

> 参考图 1 和参考图 2 **可以是同一张**（如品牌头图本身就含 IP），但调用时**必须显式声明作 2 张参考图传入**。

## 本地参考文件传参顺序（强制）

```text
referenced_image_paths: [<stylePath>, <ipPath>]
同图兼任：referenced_image_paths: [<samePath>, <samePath>]
```

参考图 1 = 风格，参考图 2 = IP。用户上传顺序不等于调用顺序；按用户指定角色排序，不去重。Stage 3 则按该次矫正步骤规定的图序传入。

## 5 套主/副主体混合约束（v1 新增 · 对应 SKILL.md 🚪 8）

> IP 模式下，**Stage 1A 的 5 套方向 + Stage 2A 的 5 套构图变体**，每一轮都必须既包含「IP 做主体」也包含「IP 做副主体」的方案，**禁止 5 套全是 IP 做主或全是 IP 做副**。

### 配比建议（5 套方案分布）

| 配比 | IP 主体方案 | IP 副主体方案 | 适用 |
| --- | --- | --- | --- |
| **3 : 2**（推荐默认） | 3 套 | 2 套 | IP 是核心识别点，但需要发散看次要场景的可能性 |
| **2 : 3** | 2 套 | 3 套 | 副主体语义更重（如功能说明 / 流程图 / 数据可视化） |
| **❌ 5 : 0** | 5 套 | 0 套 | 禁止——5 套同质化，看不出方向差异 |
| **❌ 0 : 5** | 0 套 | 5 套 | 禁止——5 套都不突出 IP，违背 IP 模式核心目标 |

### 主体 / 副主体定义

| 角色 | 视觉特征 | 例子 |
| --- | --- | --- |
| **IP 做主体** | IP 占画面 50%+，是视觉焦点，副元素围绕它服务 | IP 抱着大礼盒 / IP 坐在云朵上 / IP 拿着信号塔 |
| **IP 做副主体** | IP 占画面 15-30%，是辅助角色，画面焦点在另一物体上 | 大型功能图标主导画面，IP 在角落点缀；流程图主体，IP 在引导箭头旁解释 |

### Stage 1A 速览表写法

5 套方向的「主体」列要明确标注 IP 是主体还是副主体：

```
| 方案 | 主体 | 主打语义 |
| --- | --- | --- |
| 1 | **IP（主）** + 大礼盒 | IP 拆礼物的喜悦 |
| 2 | **IP（主）** + 信号塔 | IP 修复网络 |
| 3 | **IP（主）** + 云朵 | IP 守护数据 |
| 4 | **大功能图标**（主） + IP（副） | 功能本身是焦点，IP 引导用户 |
| 5 | **流程箭头**（主） + IP（副） | 流程主导，IP 在节点旁解释 |
```

### Stage 2A 构图变体同理

选定 1 个方向后，5 套构图变体也要在「IP 主/副」上有混合 —— 不能 5 套都是「IP 居中放大」，要有 1-2 套「IP 在画面边缘 / 角落做引导」。

### 5 套方案输出模板里的字段要求

为支持上述约束，每套方案的「主体」字段**必须显式标注「IP（主）」或「IP（副）」**，禁止只写「IP 角色」不标主副。

## IP 模式 5 套方案输出模板

```markdown
### 方案 1：【方案名称】

- 主体（标主/副）：**必填「IP（主）」或「物体名 + IP（副）」**（按参考图 2 锁定 IP 形象，**禁止写形象描述词**——不写"毛茸茸/戴围巾/圆头/紫色"等）
- 主体姿态：     # 必填：主体在做什么动作（如"双手抓断网线两头"）；不写"3D 立体/凝固瞬间/3/4 视角微仰"等触发模型走 3D 的词
- 副元素：       # 5 套差异化（断网线 / 拔插头 / 信号塔 / 云朵 / wifi 等）；IP 做副主体时，「IP 的位置和动作」也写在这里
- 副元素动态：   # 副元素如何运动
- 点缀：         # 1 个面性 X icon + 4 个同形装饰
- 构图关系：     # IP 占比（主：50%+ / 副：15-30%）+ 主副位置关系
- 中文 Prompt：   # 必须以固定句式开头（见步骤 5）
- English Prompt：# 必须以固定句式开头（见步骤 5）
```

> **配色字段在 IP 模式下省略**——风格和配色完全由参考图 1 决定，prompt 里写颜色词反而会和参考图 1 冲突。
>
> **3D 触发词黑名单**（IP 模式下严禁出现在 prompt 里）：毛茸茸 / 凝固瞬间 / 3D 立体 / 3/4 视角 / 半空悬浮 / 微微抖动 / 风中翻转 / volumetric / photorealistic。这些词会让 image2 走 3D 渲染路径，覆盖参考图 1 的扁平 UI 风。

## 调用方式（IP 模式）

**使用 Codex 内置 `image_gen`**（详见 `codex-imagegen.md`），每套方案独立调用，保持固定句式和用户指定的参考角色。

```bash
# 在 bundle.references 记录风格/IP 角色；统一入口按角色生成有序参数。
python3 <skill根目录>/scripts/director.py run <已校验的本轮bundle.json>
```

同图兼任时，在 `referenced_image_paths` 中重复同一绝对路径；不自行去重。工具是否独立使用重复槽位仍需实际运行验证。若被拒绝或去重，说明限制，不伪称已按双槽位运行。
