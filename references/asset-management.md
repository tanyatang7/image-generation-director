# 资产管理（参考图 / 本地路径 / 找回原图）

> 保留原版“先归档原图、每次核对参考、生成后立即归档”的生命周期。Codex 内置 `image_gen` 直接读取本地参考文件。

## 归档根目录

```bash
# 图片永久归档根目录，使用 Codex 项目的 outputs/generated-images 文件夹
# 从实际项目根目录运行；输出仍须遵守用户与项目规则
ARCHIVE_DIR="${IMAGE_DIRECTOR_ROOT:-$PWD}/outputs/generated-images"
```

## 核心规则（强制）

### 1. 用户上传参考图后，agent 第一时间归档原图

在 Codex 对话中，先实际查看用户提供的图片，并核对附件提供的本地路径；不搜索 Cursor transcript，也不虚构附件位置。

**Agent 必做**（用户上传图后立刻执行）：

1. 有可访问本地路径：确认原图文件，将其复制到归档目录，保留原版命名。
2. 只有对话图片但没有可访问文件：记录“原图归档未完成”，询问用户补充可归档的文件；不能声称已复制。继续不依赖文件落盘的策划，依赖原图的步骤等待补齐。
3. 只有完成原图归档后，才按所选服务的输入能力处理后续调用。

```bash
mkdir -p "$ARCHIVE_DIR/<topic>"
cp "<已核实的附件绝对路径>" "$ARCHIVE_DIR/<topic>/00-original-<purpose>.png"
```

命名规范：
- `00-original-style.png` —— 风格参考图
- `00-original-ip.png` —— IP 角色参考图
- `00-original-style-and-ip.png` —— 同时用作风格图和 IP 图（双图模式）

### 2. 使用归档后的本地参考文件

把实际存在的绝对路径按顺序放入内置工具的 `referenced_image_paths`。风格 / IP 顺序按用户已确认的角色；同图兼任时重复同一路径，不把本地文件路径冒充公网 URL。

### 3. 参考文件可用性检测（每次调用前必做）

- 确认路径存在、可读，且内容仍是对应原图；编辑前实际查看。
- 路径失效时从已归档原图恢复引用；归档也缺失则询问补图，不反复重试失效路径。
- 只有对话图没有可读文件时，先确认是否存在可访问附件路径；无法取得则说明缺失，请用户补附件，不使用内置工具的最近图片机制。

### 4. 任务完成后归档生成图

使用工具返回的真实本地输出文件，立即复制到项目归档并核对可打开；工具返回前不猜文件名。若仅提供原生媒体而没有可保存文件，先展示媒体，记录“生成已返回，文件归档未完成”，不得虚构落盘路径。

命名规范：`scheme-{NN}-{version}-{model}-{mode}.png`，例如：
- `scheme-01-v1-broken-cable.png`（v1 第 1 套）
- `scheme-03-v2-image2-ip.png`（v2 第 3 套，Image2 IP 双参考角色）
- `scheme-01-v3-gpt-image-2.png`（v3 第 1 套，Codex 内置 `image_gen`）

> 为兼容原命名模板，{model} 槽填 `gpt-image-2`；记录工具 `image_gen` 和后端 `codex-built-in-imagegen`。`gpt-image-2` 来自官方对内置能力的说明，不伪称工具调用返回了模型版本。

## 防踩坑清单（5 条）

1. **不假设参考文件一直可用** —— 每次调用前检查实际文件。
2. **本地原图必须归档** —— 不只依赖对话附件的临时路径。
3. **生成后立即归档** —— 不等用户审完才保存。
4. **续跑重新核对路径** —— 从归档与状态记录恢复，不猜上一轮临时位置。
5. **同图允许重复** —— 在 `referenced_image_paths` 中重复两次对应两个角色，保持用户指定顺序；不能把本地参数保留重复路径当作后端重复槽位已实测。
